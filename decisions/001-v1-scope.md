# 001 — v1 scope, operating contract, and the Codex statusline fork

Status: Accepted (2026-08-01)

## Context

telltale came out of a two-round, ~4M-token market research study (private record:
`career/research/next-project-stars-research.md`) that vetted 20 candidate utilities and
killed all 20 against verified incumbents. Its surviving findings: the statusline/HUD
lane is the one category where late entrants demonstrably get adopted after the vendor
shipped the underlying primitive; stars are a distribution outcome, not an engineering
one; and the success bar was therefore deliberately reset from "500+ stars" to portfolio
evidence: **daily personal use, real users, a written eval, a design doc.** Stars are
weather.

## Decision — v1 scope

1. **Claude Code in-prompt statusline** ships first and starts the dogfood clock.
   Seam verified against live docs 2026-08-01: Claude Code passes JSON on stdin to the
   statusline command — model, context `used_percentage` (input-token based),
   `total_cost_usd`, and `rate_limits.five_hour` / `.seven_day` for Pro/Max
   subscribers. No network calls; no credential reads.
2. **Minimal watch-mode HUD (TUI)** is the cross-vendor surface, with built-in adapters
   for Claude Code and Codex CLI reading vendor-native data sources. Exact Codex
   sources (session JSONL, hooks/notify events) are verified at adapter build time,
   not assumed.
3. **Documented adapter interface** — one module per vendor, a written contract, so
   users integrate other tools themselves. No plugin runtime in v1.
4. **quota-widget is absorbed and retired.** Its pacing idea becomes the statusline's
   quota segment via the native `rate_limits` fields; the private repo gets a closing
   README note. Its Tauri surface is not carried forward.
5. Out of scope for v1: Gemini CLI adapter (seam designed, not built), any desktop/web
   dashboard surface, team/multi-user features, an npm plugin system.

**Done for v1** = 2+ weeks of the author's actual daily use (calendar-measured), eval
harness + design doc shipped in-repo, then one modest launch post. In that order.

## The Codex statusline fork

The original scope assumed a cross-vendor *statusline*. First live-doc check
(2026-08-01) falsified the assumption: **Codex CLI has no statusline hook** — only open
feature requests (openai/codex #17827, #20140, #20244). Codex does expose session JSONL
and hook/notify events.

Decision: **the HUD carries the cross-vendor claim.** The statusline is Claude-only
(where the seam exists); the HUD watches both vendors through the adapter layer. All
public wording follows: "cross-vendor monitoring; vendor-native statusline where the
seam exists." Rejected: faking a Codex in-prompt line via terminal title/tmux status
(fragile workaround, contradicts the honest-gauge ethos); Claude-only v1 (ships the
differentiator as a promise). If Codex ships the hook upstream, the adapter already has
the data and the statusline gains a second vendor cheaply.

## Operating contract (DCB, binding on all sessions in this repo)

- **Honest gauge:** a segment may only display a value read from tool/vendor output;
  inferred values are omitted or visibly marked estimated; every segment's source is
  named in the design doc before it ships.
- **Live-doc verification:** vendor-format claims are checked against current
  docs/changelogs at build time, never from memory or research notes. A missing seam is
  a surfaced fork, not a silent workaround. (This rule fired once before a line of code
  was written; see above.)
- **Repo discipline:** public from day one; minimal dependencies (the statusline's own
  output is designed against a token/character budget); real design calls get ADRs; no
  metric appears in the README or launch post that isn't generated by the eval harness.
- **Bar:** eval harness in CI asserting every segment's render against fixture inputs
  for both vendors, including empty/degraded states — a segment that can't distinguish
  "no data" from "zero" fails the build. Codex adapter verified against a live session,
  not mocks only. Windows is the primary verified target; anything Unix-only is a
  flagged limitation.

## Naming

GitHub: `telltale` (no collision in this space). npm bare name `telltale` is taken by an
unrelated 1.0.0 option parser; the package name will be `telltale-hud` or a scoped name,
decided at packaging time.
